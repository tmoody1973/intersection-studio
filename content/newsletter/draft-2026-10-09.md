## What we learned

Automated systems are very good at doing exactly what they were built to do, for as long as they're running, whether or not anyone is watching.

The daily log has fired every morning for 172 days. It reads the repo state, writes an honest summary, commits it, and stops. The Mastra agents are healthy at `intersection-mastra.fly.dev/health`. The Studio Dashboard is live. The MKE Dashboard build hasn't degraded — the data's accurate, the code works, the design is intact.

The automated newsletter writer fires every Friday. It reads the git log, reads the daily log, synthesizes what happened, and writes a draft. It has done this eight weeks in a row.

What neither system can do is the last step.

That's not an automation problem. That's a decision that requires a person. The newsletter writer can produce a draft. The daily log can name the problem every day. The Studio Dashboard can surface the backlog. What they can't do is send the email, press the deploy button, or make the call on Canvas Copilot.

The automation is working. That's actually the finding.

## Deep dive: the last mile

There's a term in logistics: the last mile. It refers to the final leg of delivery — from the distribution hub to the front door. It's the shortest segment of the journey. It's also consistently the most expensive, the most failure-prone, and the hardest to optimize.

The studio has a last-mile problem.

The research is done. The designs exist. The code is written and tested. The builds deploy cleanly. The automated systems run without incident. The drafts are written. The work is, by any development metric, complete.

The last mile is: push the button.

Deploy. Send. Decide. Post. These are not hard in the technical sense. A Vercel deployment takes 90 seconds. Sending an email from a draft takes less. Opening Canvas Copilot's repo and writing "archiving this" takes five minutes.

But they require showing up — actually sitting down and doing the last small thing. And for 172 days, the last small thing hasn't happened. The automation handles everything up to that point and stops at the edge where a human has to make a call.

This isn't a critique of the last six months. Life contains other things. Radio Milwaukee is a real job. Rhythm Lab is a real show. Time is finite and attention is finite and sometimes a studio sits between active sprints.

But the gap between "built" and "shipped" is where products go to become ex-products. The MKE Dashboard isn't competing against other civic dashboards right now — it's competing against the version of itself that gets deployed. Eight newsletter drafts aren't competing against other newsletters — they're competing against the first one that gets sent.

The last mile is short. It just requires walking it.
