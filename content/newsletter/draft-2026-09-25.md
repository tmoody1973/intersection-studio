## What we learned

There's a pattern in music that maps pretty cleanly to what's happening here. A producer finishes tracks — fully mixed, mastered, sequenced — and holds them. Sometimes because the moment isn't right, sometimes because releasing means being done with a chapter, sometimes because there's always one more thing. The tracks don't deteriorate. But the window they were made for does.

The MKE Dashboard was built for a Milwaukee that needed better civic data tools. That need still exists. But tools have a timeliness problem: a neighborhood dashboard built in 2026, launched in 2027, lands differently than one launched when the work was fresh. The HOLC redlining overlay, the 30-plus data points per neighborhood, the four-language support — none of that changes by sitting. The political and civic moment it was built for does.

Six drafts. Zero sent. The newsletters document a studio that is still thinking, still honest about what's stuck. What they don't do is reach the people who might find the work useful.

There's a version of this that's still recoverable. The tracks aren't lost. They just haven't played.

## Deep dive: The security debt nobody's counting

There's a fourth item that hasn't made the top three but probably should.

The Mastra agents have P1 security items that have been open for 22-plus weeks. P1 means priority one — not a nice-to-have, not a known limitation to document. It means the system is deployed in a configuration the team already identified as insecure, and left it that way for five months.

This is worth naming separately from the "what's next" list because it's a different category of problem. Undeployed software and unshipped newsletters don't have a live risk surface. A running AI system with documented but unaddressed security gaps does. The longer it runs, the longer the window stays open.

The cultural angle here matters too. Intersection Studio builds at the intersection of culture and technology. Part of that responsibility is building systems that don't exploit the trust of the communities they're meant to serve. An AI system built to handle institutional knowledge should meet a higher bar, not a lower one.

The dormancy conversation has been about shipping and visibility — when to deploy, when to publish, when to decide. This is a different conversation. It's about whether a running system is safe to keep running. That one isn't optional, and it doesn't get resolved by drafting more newsletters about it.
